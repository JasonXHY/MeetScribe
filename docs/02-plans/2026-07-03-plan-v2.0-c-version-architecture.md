## 二、数据流

```
录音 (mic / dual)
    ↓
WAV 文件 (16kHz, mono)
    ↓
┌─────────────────────────────────────────┐
│  云端 ASR（WebSocket 流式）              │
│  输入：音频流                            │
│  输出：{text, start_ms, end_ms, spk_id} │
└──────────────┬──────────────────────────┘
               ↓
┌─────────────────────────────────────────┐
│  本地声纹匹配（CAM++ ONNX）             │
│  1. 按 spk_id 分段提取音频              │
│  2. fbank 特征提取（Rust）              │
│  3. CAM++ ONNX 推理 → 192 维向量        │
│  4. 与本地音色库余弦匹配                │
│  输出：spk_id → 姓名映射               │
└──────────────┬──────────────────────────┘
               ↓
┌─────────────────────────────────────────┐
│  双轨合并（如有双轨录音）                │
│  本地时间戳对齐，按时间排序交错          │
└──────────────┬──────────────────────────┘
               ↓
┌─────────────────────────────────────────┐
│  格式化输出 + LLM 纠错 + AI 摘要        │
│  云端 LLM API                           │
└──────────────┬──────────────────────────┘
               ↓
最终产物：{name}_transcript.md + {name}_summary.md
```

## 三、关键技术决策

### 3.1 为什么选 CAM++ ONNX 而不是全云端声纹

| 方案 | 优点 | 缺点 |
|------|------|------|
| 全云端声纹 | 安装包最小（~7MB） | 每家厂商声纹体系不通用，厂商锁定；需用户注册账号 |
| CAM++ ONNX 本地 | 声纹库本地可控，企业共享 key 无需注册 | 安装包多 ~30MB |

选择本地 CAM++ ONNX 的核心原因：**企业共享 API key 场景**。员工不需要注册任何云平台账号，企业 IT 管理员统一配置 key 即可。

### 3.2 云端 ASR 选型

建议按优先级测试：
1. **MiMo ASR**（已有 token plan，成本低，OpenAI 兼容协议）
2. **讯飞**（说话人分离最强，声纹注册 API 最完善）
3. **腾讯云**（SpeakerId 字段最友好，角色分离预付费便宜）

最终可能需要支持多厂商切换，通过配置文件选择。

### 3.3 说话人分离的两种云端方案

**方案 A：云端 ASR 自带说话人分离**
- 讯飞：roleType=2，返回 rl 字段
- 腾讯云：返回 SpeakerId 字段
- 优点：一步到位
- 缺点：MiMo ASR 不支持

**方案 B：云端 ASR + 本地聚类**
- MiMo ASR 返回纯文本
- 本地用 CAM++ 对每段提取 embedding
- 本地层次聚类分配说话人 ID
- 优点：可用 MiMo（成本低）
- 缺点：多一次本地处理，延迟略高

建议两种方案都实现，根据使用的 ASR 厂商自动选择。

## 四、待讨论的设计问题

| 问题 | 选项 | 影响 |
|------|------|------|
| 前端框架选型 | React / Vue / Svelte | 开发效率和生态 |
| 云端 ASR 是否需要多厂商支持 | 单一厂商 vs 可切换 | 架构复杂度 |
| B 版服务端是否共用 C 版前端代码 | 共用 vs 独立 | 代码复用率 |
| CAM++ ONNX 模型随安装包分发 vs 首次启动下载 | 分发 vs 下载 | 安装包大小 vs 首次使用体验 |
| 企业 API Key 配置方式 | 配置文件 / 管理后台 / 命令行 | 部署复杂度 |
