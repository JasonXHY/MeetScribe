# v2.0 C 版项目实施计划

> **For agentic workers:** 本计划为 v2.0 C 版完整实施路线图。分阶段推进，每阶段产出可验证的交付物。
>
> **协作模式：** MiMoCode（方案设计+核心实现）→ QODER（审核+UI设计+部分实现）→ 用户（决策+验证）

**Goal:** 将侧耳倾听从 v1.0（PySide6 + 2GB 本地模型）重构为 v2.0 C 版（Tauri + 云端 ASR + 本地 CAM++ ONNX，~32MB），保留全部核心功能。

**Architecture:** Tauri（Rust + Web）客户端，云端 ASR 做转写和说话人分离，本地 CAM++ ONNX 做声纹嵌入提取和匹配，云端 LLM 做 AI 摘要。企业共享 API key 模式，员工无需注册账号。

**Tech Stack:** Tauri 2.0 / Rust / React(或Vue) / ONNX Runtime (ort crate) / rustfft / ndarray / WebSocket

---

| 阶段 | 名称 | 目标 | 产出 | 预计周期 |
|------|------|------|------|---------|

## P0：技术验证（1-2 周）

> 目标：验证所有关键技术路线，发现并解决潜在问题，形成 PoC 代码。
> 原则：**不写产品代码，只做验证。每个验证项产出独立的测试报告。**

### P0-T1：CAM++ ONNX 导出验证

**负责人：** MiMoCode（执行）→ QODER（审核验证方法）

**目标：** 确认 CAM++ 可成功导出为 ONNX 格式，且推理结果与 PyTorch 一致

**任务清单：**
- [ ] 搭建 Python 导出环境（FunASR + onnxruntime）
- [ ] 编写 CAM++ ONNX 导出脚本
- [ ] 导出 CAM++ 模型为 ONNX 格式
- [ ] 用 onnxruntime Python 推理，与 PyTorch 结果对比
- [ ] 对比嵌入向量余弦相似度（目标：> 0.999）
- [ ] 记录导出后模型大小、推理耗时
- [ ] 编写验证报告

**产出文件：**
- `docs/03-reports/2026-07-XX-report-campp-onnx-export.md`
- `scripts/validate/campp_onnx_export.py`（验证脚本）

**需要讨论：**
- CAM++ 是否有已知的 ONNX 导出问题？
- 导出时是否需要量化？量化后精度损失多少？
