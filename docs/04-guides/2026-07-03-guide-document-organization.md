# 项目文档组织方法论

> 适用场景：AI Agent 协作开发的项目文档管理
> 核心目标：让 AI Agent 能快速定位所需文档，让人能清晰管理文档生命周期

---

## 一、目录结构

```
docs/
├── 00-INDEX.md              # 文档索引（Agent 入口）
├── 01-specs/                # 需求规格
├── 02-plans/                # 实施方案
├── 03-reports/              # 复盘报告
├── 04-guides/               # 开发指南
├── 05-issues/               # 问题记录
├── 06-archive/              # 历史归档
└── 99-mockups/              # 原型文件
```

### 目录职责划分

| 目录 | 存放什么 | 不存放什么 |
|------|---------|-----------|
| `01-specs/` | 功能需求、接口规格、数据模型 | 实现方案、测试用例 |
| `02-plans/` | 实施方案、架构设计、重构计划 | 已完成的方案（完成后移 03） |
| `03-reports/` | 复盘报告、审查报告、测试报告 | 进行中的分析 |
| `04-guides/` | 开发规范、工作流程、工具使用 | 项目特定的临时说明 |
| `05-issues/` | Bug 记录、问题排查、根因分析 | 已解决的问题（解决后移 06） |
| `06-archive/` | 历史文档、过时方案、旧版记录 | 当前活跃文档 |
| `99-mockups/` | UI 原型、设计稿 | 代码实现 |

### 文档生命周期

```
01-specs（需求定义）
  ↓ 设计阶段
02-plans（实施方案）
  ↓ 实施完成
03-reports（复盘总结）
  ↓ 不再活跃
06-archive（归档）
```

问题文档生命周期：
```
05-issues（问题记录）
  ↓ 修复完成
06-archive（归档）或删除
```

## 二、文件命名规范

### 格式

```
[日期]-[类型]-[简述].md
```

### 类型代码

| 代码 | 含义 | 对应目录 |
|------|------|---------|
| `spec` | 需求规格 | 01-specs/ |
| `plan` | 实施方案 | 02-plans/ |
| `report` | 复盘报告 | 03-reports/ |
| `guide` | 开发指南 | 04-guides/ |
| `issue` | 问题记录 | 05-issues/ |
| `fix` | 修复记录 | 05-issues/ |
| `review` | 代码审查 | 03-reports/ |

### 示例

```
2026-07-03-plan-scenario-testing.md      # 场景测试方案
2026-07-03-issue-transcription-timeout.md # 转写超时问题
2026-07-03-report-dual-track-audit.md     # 双轨合并审查报告
2026-07-03-guide-document-organization.md # 文档组织指南
```

### 命名原则

1. **日期在前**：便于按时间排序，一眼看出文档新鲜度
2. **类型明确**：Agent 只看文件名就能判断文档性质
3. **简述精炼**：10 个字以内概括核心内容
4. **避免特殊字符**：只用字母、数字、连字符

## 三、索引管理

### 00-INDEX.md 的作用

文档索引是 **AI Agent 的导航入口**。Agent 启动时读取索引，就知道该去哪个目录找什么文档。

### 索引内容

```markdown
# 文档索引

> 最后更新：YYYY-MM-DD
> 用途：AI Agent 文档导航入口

## 快速查找

| 类型 | 目录 | 用途 | Agent 何时读取 |
|------|------|------|---------------|
| 需求规格 | 01-specs/ | 了解项目需求 | 做技术决策时 |
| ... | ... | ... | ... |

## 最近更新

| 日期 | 文件 | 说明 |
|------|------|------|
| 2026-07-03 | 02-plans/xxx.md | 方案说明 |
```

### 索引更新时机

| 事件 | 操作 |
|------|------|
| 新增文档 | 在"最近更新"顶部添加一行 |
| 文档完成实施 | 从 02-plans 移到 03-reports，更新索引 |
| 文档归档 | 从活跃目录移到 06-archive，更新索引 |
| 超过 7 天未更新 | 从"最近更新"移除（或标注日期） |

---

## 四、目录索引（_index.md）

每个子目录可维护一个 `_index.md`，列出该目录下所有文档：

```markdown
# 02-plans 实施方案索引

| 日期 | 文件 | 状态 | 说明 |
|------|------|------|------|
| 2026-07-03 | plan-scenario-testing.md | 已实施 | 场景测试框架 |
| 2026-07-02 | plan-transcription-timeout.md | 已实施 | 转写超时修复 |
```

**可选**：如果文档数量 < 20，可不维护 `_index.md`，直接用 `00-INDEX.md` 索引。

## 五、AI Agent 协作规范

### Agent 如何使用文档

1. **启动时**：读 `00-INDEX.md` 了解文档结构
2. **排查问题时**：去 `05-issues/` 找相关问题记录
3. **执行任务前**：去 `02-plans/` 找实施方案
4. **总结进度时**：去 `03-reports/` 找复盘报告
5. **新会话开始**：读 `04-guides/` 了解开发规范

### Agent 创建文档的规则

1. **先查索引**：确认目录中没有同主题文档
2. **命名规范**：严格遵循 `[日期]-[类型]-[简述].md`
3. **内容结构**：包含现象、根因、方案、修改位置
4. **更新索引**：创建后在 `00-INDEX.md` 添加条目

### 人-Agent 协作流程

```
人提需求 → Agent 写方案(02-plans) → 人审核 → Agent 实施
  → Agent 写报告(03-reports) → 人确认 → 归档(06-archive)
```

```
人报 Bug → Agent 写排查(05-issues) → Agent 修复
  → Agent 写修复记录(05-issues/fix-*) → 归档
```

## 六、避坑指南

| 问题 | 原因 | 解决 |
|------|------|------|
| Agent 找不到文档 | 文件名无类型标识 | 严格遵循命名规范 |
| 文档堆积在根目录 | 没有目录划分 | 按类型分目录 |
| 文档过时无人清理 | 没有生命周期管理 | 定期归档到 06-archive |
| 索引与实际不一致 | 创建文档后没更新索引 | 养成创建即更新的习惯 |
| 方案和报告混在一起 | 类型代码不明确 | plan ≠ report，完成后移目录 |

## 七、快速启动清单

新项目采用本方法论时：

- [ ] 创建 `docs/` 目录和 7 个子目录
- [ ] 编写 `00-INDEX.md`（含目录说明和命名规范）
- [ ] 在项目规则中添加"文档统一放 docs/，命名遵循规范"
- [ ] 在 AI Agent 配置中指定索引路径
- [ ] 团队约定：方案在 02，完成在 03，问题在 05
